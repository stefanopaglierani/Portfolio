Edge Sentinel: Background Monitoring for Industrial PCs

By Stefano Paglierani • Est. Read: 5 mins • Industrial Automation

In industrial automation, hardware and software must operate in perfect synergy. When managing Industrial PCs (IPCs) on the factory floor, hardware degradation—such as the backup battery wearing out—can lead to catastrophic data loss during power cycles.

To prevent this without disrupting the machine's primary control software, I developed Edge Sentinel: a lightweight Python daemon designed to run silently as a native Windows Service, monitoring battery health and system telemetry strictly in the background.

1. Architecture: The Native Windows Service

Standard Python scripts are not suited for headless, persistent execution on Windows IPCs. They require open consoles and lack integration with the OS boot sequence. The architectural solution is to wrap the Python logic using win32serviceutil, turning the script into a true, native Windows Service.

This ensures the monitor starts automatically with the machine, runs under the SYSTEM account, and listens gracefully to OS-level signals (like shutdown or stop commands) rather than relying on blunt task-killing.

# --- WINDOWS SERVICE CLASS IMPLEMENTATION ---
import win32serviceutil
import win32service
import win32event

class EdgeSentinelService(win32serviceutil.ServiceFramework):
    _svc_name_ = "EdgeSentinel"
    _svc_display_name_ = "Edge Sentinel Battery Monitor"

    def __init__(self, args):
        win32serviceutil.ServiceFramework.__init__(self, args)
        self.stop_event = win32event.CreateEvent(None, 0, 0, None)

    def SvcStop(self):
        # Receives the Stop command from Windows OS
        self.ReportServiceStatus(win32service.SERVICE_STOP_PENDING)
        win32event.SetEvent(self.stop_event)

    def main(self):
        while True:
            # Replaces time.sleep(). Waits 5000ms but interrupts
            # immediately if Windows sends the Stop signal.
            rc = win32event.WaitForSingleObject(self.stop_event, 5000)
            if rc == win32event.WAIT_OBJECT_0:
                break
            
            try:
                config = carica_configurazione()
                usura = calcola_usura(config["install_date"], float(config["lifespan_years"]))
                stato = determina_stato(usura)
                salva_stato_ui(usura, stato)
            except Exception as e:
                logging.error(f"Error reading or calculating: {e}")

2. UI Decoupling and State Management

Because Edge Sentinel runs as a SYSTEM daemon, it cannot directly spawn GUI windows to warn operators. Instead, I employed a strict decoupling strategy.

The daemon calculates the wear percentage based on installation dates and expected lifespan, categorizing the health into operational zones (OK, Warning, Imminent Replacement). It then writes this state to a lightweight JSON flag file (ui_flag.json). A separate, non-intrusive UI application can monitor this file and spawn a localized popup only when the mostra_popup_allarme boolean is true.

3. Deployment: Taming Path Management in Standalone Executables

Deploying Python in an industrial setting means bypassing "dependency hell". The entire service is packaged into a standalone .exe using PyInstaller. However, converting a script to an executable fundamentally changes how the OS resolves relative paths.

To ensure the service can reliably find its local config.json and generate logs accurately regardless of where the technician drops the file, I implemented dynamic path resolution:

# --- ADVANCED PATH MANAGEMENT ---
# When the program becomes a Service or .exe, the working dir changes.
# This logic forces the program to resolve paths relative to the executable itself.
import sys
import os

if getattr(sys, 'frozen', False):
    BASE_DIR = os.path.dirname(sys.executable)
else:
    BASE_DIR = os.path.dirname(os.path.abspath(__file__))

os.chdir(BASE_DIR)

# Create directories if they don't exist (crucial on first boot)
os.makedirs('logs', exist_ok=True)
os.makedirs('output', exist_ok=True)

4. Zero-Friction Edge Integration

The final result is a robust, zero-configuration executable. Maintenance personnel can deploy Edge Sentinel on any Windows IPC simply by dropping the file and running an install flag via command line, completely isolating the monitoring logic from the primary manufacturing software stack.
